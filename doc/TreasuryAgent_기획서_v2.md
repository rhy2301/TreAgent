# TreasuryAgent v2
### AI 자율 트레저리 결제 에이전트
**Google Cloud × Solana AI Agentic Hackathon 제출 기획서**

---

## 심사 기준 매핑

| 심사 항목 | TreasuryAgent의 대응 |
|---|---|
| 혁신성 및 UX | 예정 지출을 예측해 선제 배치 — 단순 리밸런싱이 아닌 예측 기반 자금 운용. 에이전트가 왜 이 결정을 내렸는지 자연어로 보여주는 대시보드 |
| AI 활용도 | Gemini가 향후 지출 예측·실행 여부 판단·결제 경로 선택을 수행. 고정 룰이 아닌 컨텍스트 기반 LLM 추론 |

## 1. 주제

> 온체인 지갑의 예정 지출을 AI가 예측하고,
> Solana Pay(x402)로 결제까지 자율 실행하는 트레저리 에이전트

트랙: **B. Autonomous On-Chain Settlement × Fintech Treasury**

---

## 2. 왜 온체인이어야 하는가

이 질문에 먼저 답한다.

**에이전트가 자율적으로 결제하려면 다음 세 가지가 필요하다.**

1. **24시간 무중단 실행** — 은행은 영업시간이 있고 사람은 잠을 잔다. 온체인 지갑은 항상 열려 있다.
2. **중간 승인자 없는 서명** — 전통 금융은 결제 실행에 반드시 사람 또는 기관의 승인이 필요하다. Solana에서는 에이전트가 프라이빗 키로 직접 서명하고 즉시 실행된다.
3. **변조 불가능한 실행 이력** — 에이전트가 왜, 언제, 얼마를 보냈는지 온체인에 영구 기록된다. 감사(audit)에 별도 시스템이 필요 없다.

→ 이 세 가지를 동시에 충족하는 환경이 Solana다.

## 3. 타겟 사용자

| 구분 | 대상 | 공통 문제 |
|---|---|---|
| **Primary** | Web3 스타트업 / DAO 재무팀 | 여러 온체인 지갑 잔고를 수동 모니터링, 수동 이체 |
| **Secondary** | 크립토 결제 서비스 운영사 | 결제 지갑 잔고 부족으로 결제 실패 리스크 상존 |

**핵심 페인포인트**: 예정된 결제(급여, 벤더 비용, API 이용료)가 있는데 결제 지갑 잔고가 부족해도, 담당자가 수동으로 확인하기 전까지 아무도 모른다.

## 4. 핵심 문제 정의

### 현재 상황

```
[매주 금요일 DAO 기여자 급여 지급 시]

재무 담당자:
  → 급여 지갑 잔고 수동 확인
  → 트레저리 Vault 잔고 확인
  → 부족분 계산 (수동)
  → Vault → 급여 지갑 USDC 이체 실행
  → 각 기여자 주소로 개별 송금
  → 소요 시간: 1~2시간, 야간·주말 대응 불가
```

### 이걸 에이전트가 처리하면

```
[매주 금요일 도래 전, 에이전트가 자율 처리]

  → 급여 스케줄 데이터 참조 (예: 금요일 14명, 총 28,000 USDC)
  → 급여 지갑 현재 잔고 확인 (5,000 USDC)
  → Gemini 판단: "부족분 23,000 + 버퍼 2,000 = 25,000 USDC 이동 필요"
  → Vault에서 급여 지갑으로 USDC 자율 이체
  → 지급일 도래 시 Solana Pay(x402)로 각 기여자에게 자동 송금
  → 전 과정 온체인 기록
```

## 5. 서비스 구조

### 온체인 지갑 구조 (CEX 아님)

```
[Treasury Vault]          ← 주요 USDC 보유고 (운영 자금)
      ↓ 자율 이동
[Operations Wallet]       ← 일상 운영비 (API 비용, 도구 구독료 등)
[Payroll Wallet]          ← 기여자 급여 지급용
[Vendor Wallet]           ← 외부 벤더 정산용
```

모든 지갑은 Solana 온체인 주소이며, 에이전트가 프라이빗 키를 보유해 직접 서명 가능.

### 핵심 플로우

```
[1] 예정 지출 스케줄 로드
    급여 데이터, 벤더 계약, 예약된 결제 항목 수집

[2] Gemini 예측 및 판단
    입력:
      - 각 지갑 현재 잔고
      - 향후 72시간 예정 지출 목록
      - 각 지갑별 최소 운영 버퍼
      - 일일 / 1회 이체 한도 정책
    출력:
      - 어떤 결제가 실패 위험에 처했는가
      - 어떤 지갑에 얼마를 언제까지 채워야 하는가
      - 직접 USDC 전송인가, 토큰 스왑이 필요한가
      - 지금 실행할 것인가, 대기할 것인가

[3-A] USDC 직접 전송 (스왑 불필요 시)
    Vault → 대상 지갑으로 SPL USDC 전송
    에이전트가 직접 트랜잭션 서명 & 제출

[3-B] 토큰 스왑 후 전송 (Vault에 SOL만 있는 경우)
    Jupiter에서 SOL → USDC 최적 경로 조회
    슬리피지 · 수수료 허용 범위 내인지 확인
    스왑 실행 → 대상 지갑으로 USDC 전송

[4] Solana Pay (x402) 실제 결제 실행
    결제 지갑에 자금 확보 완료 후
    x402 프로토콜로 수신자(기여자/벤더)에게 결제 요청 처리
    에이전트가 직접 서명 → USDC 즉시 정산

[5] 온체인 기록 & 대시보드 업데이트
    트랜잭션 해시, 실행 시각, Gemini 판단 근거 함께 기록
```

### 정책 · 예산 제어

에이전트는 사람이 사전 설정한 정책 범위 안에서만 실행된다.

```
설정 예시:
  - 1회 이체 한도: 최대 10,000 USDC
  - 일일 총 실행 한도: 50,000 USDC
  - 허용 수신 지갑 화이트리스트
  - 허용 스왑 슬리피지: 최대 0.5%
  - 한도 초과 시: 실행 중단 + 담당자 알림 발송
```

## 6. 기술 스택 및 역할

### Solana 결제 스택

| 기술 | 역할 | 언제 사용 |
|---|---|---|
| **USDC (SPL Token)** | 모든 정산의 기준 통화 | 지갑 간 이동, 최종 결제 전 과정 |
| **Solana Pay / x402** | 실제 결제 실행 프로토콜 | 기여자 급여, 벤더 정산, API 이용료 지급 |
| **Jupiter Aggregator** | 토큰 스왑 최적 경로 | Vault에 SOL만 있고 USDC가 필요한 경우에만 |
| **Solana 트랜잭션 서명** | 에이전트 자율 실행 | 모든 자금 이동 및 결제 실행 시 |

**Jupiter 사용 조건 명확화**:
- USDC → USDC 이동: Jupiter 불필요, SPL 직접 전송
- SOL → USDC 변환 필요 시: Jupiter로 스왑 경로 조회 후 실행
- 다른 SPL 토큰 → USDC 필요 시: Jupiter 사용

### Google Cloud AI 스택

| 기술 | 역할 | 구체적 동작 |
|---|---|---|
| **Gemini** | 예측 · 판단 · 실행 근거 생성 | "결제 지갑에 72시간 내 28,000 USDC 필요. 현재 5,000. Vault에서 25,000 이동 권장. 이유: 금요일 14명 급여 지급 예정" |
| **Vertex AI** | 지출 패턴 분석 | 과거 지출 이력 기반 향후 필요액 예측 정확도 개선 |
| **Cloud Run** | 에이전트 루프 실행 | 15분 간격 모니터링 루프를 서버리스로 24/7 구동 |

**AI가 단순 룰 엔진과 다른 이유**:
Gemini는 "잔고 < 임계치 → 이체"의 고정 로직이 아니라, 예정 지출 데이터 + 현재 잔고 + 시장 수수료 + 정책 한도를 종합해 자연어로 판단 근거를 생성한다. 이 근거가 대시보드에 표시되어 운영자가 에이전트의 행동을 이해하고 신뢰할 수 있게 된다.

## 10. 백데이터

### 문제의 실재성

- 전 세계 DAO의 **78%**가 재무 운영(급여, 벤더 정산)을 여전히 수동으로 처리 (DeepDAO, 2024)
- Web3 스타트업 재무팀이 잔고 모니터링 및 이체 작업에 쏟는 시간: 주당 평균 **6~10시간** (Multis Treasury Report, 2023)
- 크립토 결제 지갑 잔고 부족으로 인한 결제 실패율: 전체 온체인 결제의 약 **12%** (Chainalysis, 2024)

### Solana 인프라 우위

- Solana 트랜잭션 최종성: **400ms** (Ethereum 12초 대비 30배 빠름)
- 평균 트랜잭션 수수료: **$0.00025** (Ethereum 대비 99.9% 저렴)
- Solana Pay 누적 결제 건수: **1억 건 이상** (2024 기준)
- USDC on Solana 일일 거래량: **$4B~$8B** (Circle, 2024)

### AI 자동화 수요

- Gartner: 2026년까지 기업 재무팀의 **80%**가 AI 에이전트 기반 자동화 도입 전망
- AI 기반 재무 자동화 도입 기업의 운영 오류율 감소: 평균 **67%** (Deloitte, 2024)
- 자율 결제 에이전트 시장: 2024년 $1.2B → 2028년 $9.8B 예상 (MarketsandMarkets, 2024)

### 경쟁 공백

| 서비스 | 제공 기능 | 없는 것 |
|---|---|---|
| Gnosis Safe | 멀티시그 지갑 관리 | 자율 판단 없음, 사람 승인 필요 |
| Superfluid | 스트리밍 결제 | 예측 기반 자금 배치 없음 |
| Request Finance | Web3 청구서 · 급여 | 에이전트 자율 실행 없음 |
| Coinshift | 트레저리 대시보드 | AI 판단 없음, 수동 실행 |

→ **"예측 기반 자금 배치 + AI 자율 판단 + Solana Pay 실제 결제 실행"을 하나로 묶은 솔루션은 현재 없음**

## 11. 확장 로드맵

```
Phase 1 — 해커톤 MVP
  단일 에이전트 / 3개 지갑 / Solana Devnet
  급여 지급 시나리오 1개 데모

Phase 2 — 메인넷 전환
  실제 USDC 정산 / 다수 지갑 지원
  Jupiter 스왑 시나리오 추가

Phase 3 — Multi-Agent (트랙 C 확장)
  재무 에이전트 ↔ 결제 에이전트 ↔ 감사 에이전트
  에이전트 간 협상 및 실행

Phase 4 — 엔터프라이즈
  ERP 연동 / 규제 컴플라이언스 레이어
  멀티체인 지원
```
